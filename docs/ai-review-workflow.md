# 여러 AI로 문장 검수하기

> 강의 원고의 문장을 Gemini·ChatGPT·Claude가 나눠 검수할 때 읽는다. 2026-11-22 첫 전체 검수(21편)에서 정한 규칙이다. 문장 기준 자체는 `편집규칙.md` 2·3·5절과 `docs/kimjuhwan-style.md`가 원본이다. 이 문서는 **누가, 어떤 순서로, 무엇을 기준으로 판정하는지**만 정한다.

## 1. 범위
- 대상: `data/mini_courses.json`의 `lead`·`three`(옛 형식), `data/lecture_compact.json`의 `intro`(핵심 문장·해볼 일의 세 칸·단계)·`practice`(옛 형식)·`detail`. 도입의 `quote`는 강연자의 말이므로 검수 대상이 아니다(고칠 수 없다).
- 하는 일: 사실을 그대로 두고 문장을 자연스럽게 다듬는다.
- 하지 않는 일: 자막 재추출, 학술 주장 재검증, 타임스탬프 수정, 화면 문구 수정, 생성 HTML 직접 편집.

## 2. 역할
| 역할 | 담당 | 하는 일 |
|---|---|---|
| 1차 검수 | Gemini | 문장 자연스러움·번역투·형식 점검. 제안과 이유를 JSON으로 낸다. |
| 2차 독립 검수 | ChatGPT(Codex) | 1차 결과를 보지 않고 같은 양식으로 검수한다. |
| 기계 점검·자동 반려 | `scripts/ai_review/` | 형식 위반과 반복되는 잘못된 제안을 먼저 거른다. |
| 판정·사실 대조·반영 | Claude | 남은 제안을 하나씩 판정하고, 자막으로 사실을 확인하고, 데이터에 반영한다. |
| 최종 승인 | 사용자 | 판정 기준과 결과를 승인한다. 사용자가 맡기면 Claude의 권장안대로 반영한다. |

- 자기 제안을 자기가 판정하지 않는다. 두 검수는 서로의 결과를 보지 않는다.
- 이미지가 필요하면 ChatGPT만 쓴다(역할 분담 메모와 같다).

## 3. 절차
작업 단위는 강의 1편이다. 3편씩 7배치로 돈다. 산출물은 `drafts/ai-review/batches/NN/`에 쌓이고 저장소에 올리지 않는다.

```bash
PYTHONPATH=scripts python3 -m ai_review.run_batch 1   # 1–7
```

배치 하나는 다음 순서로 돈다.
1. 기계 점검: `lead`·`three`·`intro` 형식, 김주환 강의의 ‘강사는’ 금지어.
2. Gemini 검수 → ChatGPT 검수. 같은 프롬프트(`scripts/ai_review/review_prompt.md`)를 쓴다.
3. 형식 검증: JSON 배열인지, 필수 키와 허용 값인지, `original`이 원문에 실제로 있는지.
4. 자동 반려(4절).
5. 묶기: 두 검수가 같은 필드에 같은 제안 → 합의, 다른 제안 → 상충, 한쪽만 → 검토, `meaning_change: true` → 사용자 판단.
6. Claude 판정(5절)과 사실 대조(6절).
7. 판정 표를 `docs/ai-review-<날짜>/`에 남긴다.

## 4. 자동 반려
아래는 사람이 판정하지 않고 바로 반려한다. 파일럿에서 매번 반려한 유형이다.
- 원문과 제안이 같다.
- 인용형 `lead`(큰따옴표로 감싼 발언)를 고친다. 인용은 자막 낱말을 유지하고, 다듬기는 Claude가 최소 범위로 한다(편집규칙 2절).
- 제안이 원문에 없던 번역투(‘에 대한’, ‘를 통해’, ‘을 통해’, ‘에 의해’)를 더한다.
- 고친 뒤의 `lead`·`three`·`intro` 칸이 길이·쉼표·문장 끝 기준을 어긴다.

## 5. 판정 기준 (Claude)
**채택**: 뜻이 같고 문장이 확실히 나아진다.
- 주술 호응, 수식 관계, 병렬 구조가 어긋난 문장을 바로잡는다.
- 빠진 조사(인용격 ‘고·라고’ 등)나 단위를 채운다.
- 무생물 주어 구문을 풀되 출처 표시는 남긴다.

**사용자 판단으로 보내고 원문 유지**: 뜻이 조금이라도 바뀐다.
- ‘~라고 한다’ 같은 전달 표지를 지워 단정이 된다.
- 비유를 다른 비유로 바꾼다.
- 비교 대상이나 주어가 바뀐다.
- 위 경우라도 원문이 비문이면, Claude가 뜻을 유지한 최소 수정안을 따로 쓴다. 그 수정안은 판정 표에 ‘Claude 수정’으로 표시한다.

**반려**
- 원문에 없는 내용을 더하거나 있던 정보를 뺀다.
- 표준 어휘나 허용되는 띄어쓰기를 오류로 본다(예: 캐묻는다는 뜻의 ‘신문(訊問)’).
- 자막과 맞지 않는다(6절).
- `meaning_change`를 false로 적었지만 실제로 뜻이 바뀐다.

같은 필드에 상충 제안이 있으면 두 안과 원문을 함께 놓고 고른다. 순서 편향을 피하려고 두 안의 순서를 바꿔 한 번 더 읽는다.

## 6. 사실 대조
- 뜻에 닿는 제안은 `transcripts/<영상ID>.ko.txt`에서 해당 표현을 찾는다.
- 자막에 원문 표현의 근거가 있으면 그 표현을 지우는 제안은 반려한다(예: ‘양육자의 혼잣말’, 1:25:33).
- 자막에서 근거를 찾지 못하면 채택하지 않는다.

## 7. 반영
- 채택 항목만 데이터의 해당 필드에서 `original`을 `suggestion`으로 바꾼다. 같은 필드에 `original`이 정확히 한 번 있어야 한다.
- 반영 뒤 두 생성기를 다시 돌리고 `build-info.json`의 `version`을 올린다.
- `AGENTS.md`의 검증 명령을 모두 통과한 뒤 PR → CI → squash 머지 → 공개 페이지 확인 순서로 끝낸다.

## 8. 기록
- 배치별 판정 표와 전체 요약: `docs/ai-review-<날짜>/`.
- 각 AI의 원 출력과 프롬프트: `drafts/ai-review/batches/NN/`(저장소 밖, `.gitignore`).
- 바뀐 강의는 판정 표의 항목 번호로 찾을 수 있게 한다.

## 9. 파일럿에서 배운 점 (2026-11-22)
1. Gemini는 인용형 `lead`를 다듬으려 한다. 프롬프트에 금지 문장을 두고 자동 반려로도 막는다.
2. 두 검수가 같은 필드를 고르는 일은 드물다. 합의만 기다리면 채택할 것이 없다. 한쪽만 낸 제안도 Claude가 판정한다.
3. 배치 전체 상한(20개)은 ChatGPT가 금방 채운다. 상한은 강의마다 10개로 둔다.
4. ‘오탈자’ 라벨이 낱말 선택에도 붙는다. 프롬프트에 유형 기준을 적는다.
5. 제안 문장에 번역투가 섞인다. 제안에도 같은 금지 규칙을 적용한다.

## 10. 다른 저장소 규칙과의 관계
홈페이지 저장소의 `gmchurch_web/docs/ai-orchestration.md`(2026-11-21)와 원칙이 같다. 겹치는 원칙은 아래와 같다.
- AI 답은 데이터다. 근거 없는 주장은 채택하지 않는다.
- 두 모델은 서로의 답을 보지 않게 따로 부른다.
- 결정적인 점검은 스크립트가, 판단은 모델과 Claude가 한다.
- 모델의 자가 보고는 믿지 않는다. 이번 검수에서도 뜻이 바뀐 제안에 `meaning_change: false`가 붙은 사례가 있었다.
- 저장소 쓰기와 머지는 Claude만 한다. Codex는 읽기 전용(`-s read-only`)으로 부른다.

이 문서가 더한 것은 원고 검수에 맞춘 세 가지다. 자동 반려 규칙(4절), 자막 대조(6절), 강의마다 상한(9절 3번)이다.

## 11. 근거로 삼은 자료
- 다른 계열 모델이 검수하면 같은 모델 검수가 놓치는 부분을 줄일 수 있다. 다만 결과는 과제와 프롬프트에 따라 다르고, 글쓰기에 대한 직접 근거는 적다. [When Does a Second Model Help?](https://arxiv.org/pdf/2610.01471)
- LLM 심판에는 순서 편향과 자기 선호 편향이 있다. [Judging the Judges](https://arxiv.org/html/2406.07791v5)
- 여러 모델이 의견을 맞추면 불확실한 사실이 줄 수 있지만 비용이 크다. [Du et al., arXiv:2305.14325](https://arxiv.org/abs/2305.14325)
- ‘-어지다·-되다’를 일괄로 피하지 않는다는 국립국어원 측 의견: 편집규칙과 `docs/kimjuhwan-style.md`의 번역투 점검을 따른다.
