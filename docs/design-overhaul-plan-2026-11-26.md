# 전면 디자인 개편 계획 v16 (2026-11-26)

> 이 문서는 계획이다. 이 문서만으로 화면은 바뀌지 않는다. 단계마다 PR 하나를 만들고, 구현하는 PR에서 `docs/design-system.md`·토큰·검사를 함께 고친다. 단계가 끝날 때마다 아래 진행 표를 갱신한다.

## 1. 왜 다시 짜는가
2026-11-26 공개 사이트를 390×844px와 1280×900px, 라이트·다크로 캡처해 확인했다.

- **홈:** 제목 → 오늘의 한 문장 → 검색·칩·정렬 상자 → 카드 목록이 한 열로 쌓인다. 모바일 첫 화면에는 카드가 1.5장만 보인다. PC는 800px 폭이라 좌우가 비어 있다.
- **상세:** 제목 → 메타 → 읽음 표시 → 대표 이미지 → 탭형 목차 → 핵심 요약 순이다. 모바일에서 대표 이미지가 첫 화면의 약 절반(240px)을 차지해 핵심 요약 제목이 첫 화면 맨 아래(약 680px)에 걸린다.
- **누적:** v10부터 v15와 여러 보완을 덧대 오면서 `site.css`가 1,363줄(98KB)이 됐다. 오늘의 문장·검색 상자·카드의 상자 모양이 서로 다르다.
- 2026-11-20 계획은 전면 재디자인(B안)을 뺐다. 이번에는 사용자가 전면 개편을 직접 요청했다(2026-11-26).

## 3. 차용하는 최신 디자인 요소
읽기를 돕는 것만 골랐다. 3D, 맥시멀리즘, 안티디자인처럼 읽기를 방해하는 경향은 쓰지 않는다. 트렌드 출처는 대부분 업체 블로그라서 순위가 아니라 여러 출처에서 겹치는 요소만 근거로 삼았다.

| # | 요소 | 적용 | 기대 효과 |
|---|---|---|---|
| 1 | 벤토 그리드 | 홈 위쪽을 타일로 묶는다. 큰 타일=오늘의 한 문장, 작은 타일=이어 읽기·주제 4개(편수)·최근 추가·많이 본 강의. PC 4열, 모바일 2열 | 첫 화면에서 갈 곳이 다 보인다 |
| 2 | 리퀴드 글래스(층이 있는 반투명 UI) | 헤더·모바일 하단 도구 막대·목차 시트·검색 팔레트에만 쓴다. 본문 면에는 쓰지 않는다. `prefers-reduced-transparency`와 `backdrop-filter` 미지원 때는 불투명 면 | 떠 있는 조작부와 본문의 경계가 분명하다. iOS 26 시각 언어와 맞다 |
| 3 | View Transitions·스크롤 연동 애니메이션 | 카드 제목 → 상세 제목 문서 간 전환(`@view-transition { navigation: auto }`). 읽기 진행 막대를 CSS `animation-timeline: scroll()`로 옮긴다 | 페이지를 옮겨도 맥락이 이어진다. 진행 막대 JS 보간을 줄인다 |
| 4 | 명령 팔레트식 즉시 검색 | `/`·⌘K·모바일 하단 막대 검색 버튼. 제목·한 줄 요약·태그·상세 요약 소제목을 찾고 소제목 앵커로 바로 간다. 색인은 생성기가 정적 JSON으로 만든다 | 상세 페이지에서도 다른 강의를 바로 찾는다 |
| 5 | 표현력 있는 타이포·Material 3 Expressive 모양과 움직임 | `clamp()` 유동 글자 크기, 큰 디스플레이 제목, 반경 단계(8·20·28px), `linear()` 스프링 곡선의 북마크·읽음·복사 피드백 | 한 문장이 주인공이 되고 누른 반응이 바로 보인다 |

기반: 엄지 영역 하단 막대(목차·검색·보기·맨 위로)가 지금의 오른쪽 아래 목차 버튼(`outline-fab`)을 대신한다. 컴포넌트 크기는 컨테이너 쿼리로 맞춘다. 접근성은 WCAG 2.2(터치 44px, 대비 4.5:1, 동작·투명도 줄이기)를 따른다.

## 4. 바꾸지 않는 것
- 강의 본문과 데이터, 타임스탬프 원문과 복사 계약(`design-system.md` 3절), 기존 URL 앵커(`#lecture-overview`, `#detail-N`, `#lecture-sources` 등), 생성기가 HTML을 만드는 구조.
- Material 블루 색 역할, 라이트·다크, 강조 색·글자 크기 보기 설정, 오프라인·PWA 동작.
- 사용자가 직접 정한 것: `word-break:break-all`(2026-11-21), 스크롤 시 헤더 자동 숨김(2026-11-21), 타임스탬프 임베드·막대 없음(2026-11-23), 학습 기록·로그인 화면 없음, 상단 전역 메뉴 없음.

**공통 접근성 조건 (S2a부터 모든 PR의 병합 조건):** 새 조작부는 키보드만으로 열고 닫고 이동할 수 있다. 열면 포커스가 안으로 가고 닫으면 원래 자리로 돌아온다. 버튼마다 접근성 이름이 있다. 터치 대상 44px, 대비 4.5:1. `prefers-reduced-motion`·`prefers-reduced-transparency`에서 움직임과 반투명을 끈다. Playwright 검사로 확인한다.

**검색 색인과 오프라인 계약 (S2b):** 색인 파일 이름에 내용 해시(`?v=`)를 붙이고 서비스 워커 사전 캐시 목록에 넣는다. 배포가 바뀌면 SW 버전이 바뀌어 옛 색인을 지운다. 페이지와 색인은 같은 버전끼리만 쓴다. 첫 방문 오프라인(색인 없음: 검색 버튼이 '오프라인에서는 검색할 수 없음'을 알린다)과 업데이트 직후(새 페이지 + 새 색인) 시나리오를 검사한다.

## 6. 완료 기준 (측정으로 확인)
판정은 S0.5에서 넣는 Playwright 측정 검사가 한다. 기본 글자 크기·라이트 테마, 홈과 고정 강의 두 편(대표 이미지가 있는 `QmOF0crdyRU`, 상세 요약이 가장 긴 `MdDj5RZkMB4`)에서 잰다.
- 390×844 홈: 오늘의 한 문장과, 링크·버튼으로 된 행선지(벤토 타일·카드) 6개 이상의 상자 아래 끝이 844px 안에 있다.
- 390×844 상세: 핵심 요약 첫 항목 상자의 아래 끝이 844px 안에 있다.
- 레이아웃 이동: 로드 후 3초 동안 `PerformanceObserver('layout-shift')` 합이 0.01 미만(사실상 0).
- 용량: 원본 파일 기준(최소화하지 않음) `site.js`는 지금 29,254바이트를 넘지 않는다. 검색 색인은 50KB 이하. 서비스 워커 사전 캐시 총량은 지금보다 10% 넘게 늘지 않는다(S0.5에서 현재 값 기록).
- 가로 넘침 없음: 360·390·768·1024·1280px과 각 분기점 ±1px, 390×844 가로 모드(844×390), 글자 작게·보통·크게, 라이트·다크.
- 200% 확대(1280px 창에서 640px 폭 상당)에서 내용이 잘리지 않는다.
- 기존 검증 명령(AGENTS.md)과 Playwright 전체가 통과한다.

## 9. 위험
- 계산 스타일 검사가 많아 S1·S3에서 검사 수정이 크다. 검사 수정과 화면 수정을 같은 PR에 넣고, 바뀐 기준을 PR 본문에 적는다.
- 문서 간 View Transitions는 Chromium 계열과 Safari 18.2 이상에서만 동작한다. 그 밖에서는 효과 없이 이동한다.
- `backdrop-filter`는 저사양 휴대폰에서 스크롤을 느리게 할 수 있다. 작은 면에만 쓰고 불투명 대체를 둔다.
- 하단 막대가 iPhone 홈 인디케이터·Safari 하단 주소창과 겹칠 수 있다. `env(safe-area-inset-bottom)`을 쓰고, 실기기 Safari는 미검증으로 남긴다.
- 홈 폭을 넓히면 헤더·푸터의 왼쪽 선 정렬(홈 1120px, 상세 800px)이 페이지마다 달라진다. 헤더 폭을 페이지 폭에 맞춘다.
