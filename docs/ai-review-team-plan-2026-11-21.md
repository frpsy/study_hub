# 다중 AI 문장 검수 팀 계획

작성일: 2026-11-21 · 대상: 강의 원고 21편(`data/mini_courses.json`, `data/lecture_compact.json`)
상태: **계획 초안.** 실행 전 사용자 승인이 필요하다. 파일 수정과 PR은 이 계획에 포함하지 않는다.

## 1. 목적과 범위

- 목적: 사실을 바꾸지 않고, 문장을 자연스럽고 읽기 쉽게 다듬는다.
- 범위: 강의 원고 21편의 `lead`(한 문장), `three`(핵심 세 가지), `practice`(실천 포인트), `detail`(상세 요약) 중 **문장 편집**만 다룬다.
- 제외: 자막 재추출, 학술 주장의 재검증, 타임스탬프 수정, 화면 문구(홈·UI), 생성 HTML 직접 편집.
- 완료 기준은 4절에서 정한다.

## 2. 확인된 사실과 제약

확인된 사실:
- 문장 기준은 4곳에 나뉘어 있다: `AGENTS.md`, `편집규칙.md` 2·3·5절, `docs/kimjuhwan-style.md`, 역할 분담 메모.
- 역할 분담은 이미 정해져 있다: Gemini 1차 검수, ChatGPT·Haiku 대체, Claude 최종 확정, 이미지는 ChatGPT만.
- 2026-11-01에 화면 문구와 강의 6편을 3단계로 교정한 기록이 있다(`docs/language-review-2026-11-01.md`). 이 흐름을 기준선으로 쓴다.

지켜야 할 제약(편집규칙에서 가져옴):
- `lead`는 정확히 한 문장, 60~120자, ‘-다.’로 끝난다. 인용형 `lead`는 예외가 있다.
- `three` 각 항목은 한 문장, 70자 안팎(최대 90자), 쉼표 1개 이하.
- 김주환 강의 본문에는 "강사는·강사의·강사가"를 쓰지 않는다. 테스트가 검사한다.
- 편집자 주는 본문이 아니라 `editor` 필드에 둔다.
- 기존 ID·앵커·URL은 바꾸지 않는다.

외부 조사에서 얻은 근거(요약, 원문 확인은 아직 안 함):
- 다른 모델이 검수하면 같은 모델 검수가 놓치는 맹점을 줄일 수 있다는 실험이 있다. 다만 결과가 일관되지 않고, 검수 프롬프트와 문맥 설계에 따라 달라진다. 글쓰기·교정에 대한 직접 근거는 적다. [When Does a Second Model Help?](https://arxiv.org/pdf/2610.01471), [Cross-Model LLM Code Review](https://arxiv.org/pdf/2607.21656)
- 여러 모델이 토론하면 사실 오류가 줄 수 있다는 연구가 있다(Du et al., ICML 2024). 비용은 많이 든다. [arXiv:2305.14325](https://arxiv.org/abs/2305.14325)
- LLM 심판은 **순서 편향**과 **자기 선호 편향**이 있다. 순서를 바꿔 두 번 보고, 자기가 쓴 결과를 자기가 판정하지 않게 한다. [Judging the Judges](https://arxiv.org/html/2406.07791v5)
- 국립국어원 측 자료는 ‘-어지다·-되다’를 일괄로 피하는 것에 반대한다. 그래서 번역투 점검은 “무조건 바꾸기”가 아니라 “더 자연스러운 쪽 고르기”로 한다. 공식 2026 지침은 찾지 못했다. [GQ Korea 기사](https://www.gqkorea.co.kr/2016/06/12/%ED%96%88%EC%97%88%EC%97%88%EB%8B%A4%EB%8A%94-%ED%8B%80%EB%A6%B0-%ED%91%9C%EA%B8%B0%EC%9D%B8%EA%B0%80-%ED%95%9C%EA%B5%AD%EC%96%B4-%EB%AC%B8%EB%B2%95/)

## 3. 팀 구성

| 역할 | 담당 | 하는 일 | 하지 않는 일 |
|---|---|---|---|
| 지휘(Claude) | Claude | 조각 나누기, 양식 배포, 결과 취합, 충돌 판정, 사실 대조, 사용자 승인 표 작성 | 원문 임의 수정 |
| 1차 검수 | Gemini | 문장 자연스러움, 번역투, 길이·쉼표 점검. 항목별 제안과 이유 | 사실 판단 |
| 2차 독립 검수 | ChatGPT(Codex) | **Gemini 결과를 보지 않고** 같은 양식으로 독립 검수 | 1차 결과 보기 |
| 기계 점검 | 스크립트(Haiku는 보조) | 글자 수, 쉼표 수, 금지어, 문장 수, 필수 필드 확인 | 문장 판단 |
| 최종 승인 | 사용자 | 반영할 항목 선택 | — |

설계 이유:
- Gemini와 ChatGPT를 분리하고 blind 방식을 쓰면, 같은 모델의 편향이 겹쳐 생기는 맹점을 줄인다.
- 기계 점검을 먼저 돌리면 AI 호출 비용을 줄이고, 형식 오류를 판단 단계에 넘기지 않는다.
- Claude는 제안을 만들지 않고 취합과 판정만 한다. 역할을 섞으면 최종 판정이 흐려진다.

## 4. 작업 단위와 순서

**작업 단위:** 강의 1편 = 1개 항목(`lead`, `three`, `practice`, `detail`을 묶는다). 21편은 **7배치 × 3편**으로 나눈다. 김주환 강의 17편과 그 외 강연자 4편(Brooks, Panda, Huberman 2편)을 섞어 배치한다.

**단계:**

0. **기준선 고정.** 현재 데이터를 스냅샷으로 저장하고 기계 점검 결과를 기록한다. 기준 문서 4곳의 규칙을 한 장짜리 체크리스트로 합친다. 체크리스트에 없는 규칙은 넣지 않는다.
1. **기계 점검.** 스크립트로 형식 위반만 찾는다. 결과는 배치별 목록으로 남긴다.
2. **1차 Gemini 검수.** 배치 1개를 Gemini에 준다. 출력은 아래 양식의 JSON이다.
3. **2차 ChatGPT 독립 검수.** 같은 배치를 ChatGPT에 준다. Gemini 결과는 주지 않는다. 항목 순서는 Gemini와 다르게 섞는다.
4. **Claude 취합과 판정.** 두 결과를 항목별로 맞춘다. 판정 규칙은 5절.
5. **사실 대조.** 의미가 바뀌는 제안은 `transcripts/`와 `study-audits/`의 근거와 맞춰 본다. 근거가 없는 제안은 채택하지 않는다.
6. **사용자 승인 표.** 배치별로 "원문 → 제안 → 이유 → 판정"을 한 표로 보낸다. 사용자가 항목을 고른다.
7. **반영(이 계획 밖).** 승인된 항목만 데이터에 반영하고, 생성기와 검증을 돌린 뒤 PR로 올린다. `AGENTS.md`의 기본 흐름을 따른다.

**시험 배치(파일럿):** 첫 배치는 김주환 강의 3편으로 한다. 후보는 `2VTv6WW8Kn8`(감사), `kLizfh-5vuE`(존중), `MdDj5RZkMB4`(우리를 힘들게 하는 것). 파일럿에서 양식과 판정 규칙을 고치고 나서 나머지 6배치를 돌린다.

**AI 출력 양식(항목 1개당):**

```json
{
  "lecture_id": "2VTv6WW8Kn8",
  "field": "three[1]",
  "original": "원문 문장",
  "suggestion": "제안 문장",
  "type": "번역투|쉼표|길이|어색한 연결|오탈자|유지",
  "reason": "한 줄 이유",
  "meaning_change": false,
  "confidence": "높음|중간|낮음"
}
```

- `meaning_change`가 `true`이면 자동 채택하지 않는다. 사용자 판단 큐로 보낸다.
- 제안이 없으면 `type: "유지"`로 기록한다. 빈 칸으로 두지 않는다.

## 5. 판정 규칙

| 상황 | 처리 |
|---|---|
| 두 AI가 같은 제안 | 채택 후보. 사실 대조 후 승인 표에 올린다. |
| 한 AI만 제안 | 검토 후보. 근거가 분명하면 승인 표에 올린다. |
| 제안이 서로 다름 | Claude가 두 안과 원문을 비교해 한 안을 고르고 이유를 적는다. 고르기 어려우면 사용자에게 보낸다. |
| `meaning_change: true` | 사용자 판단 큐. 자동 반영 금지. |
| 기계 점검 위반인데 AI가 "유지" | 기계 점검을 우선한다. 위반 사유를 승인 표에 적는다. |
| 번역투 제안 | "더 자연스러운 쪽 고르기"로 판정한다. 원문이 자연스러우면 유지한다. |

순서 편향 대응: 두 안을 비교할 때는 순서를 바꿔 두 번 보고, 두 번 같은 결과일 때만 채택한다.

## 6. 성공 기준과 측정

- 사실 훼손: 의미가 바뀐 채택 항목 **0건**이 목표다. 한 건이라도 나오면 그 배치는 재검수한다.
- 형식 위반: 기계 점검 위반 **0건**으로 반영한다.
- 채택률: 승인 표 항목 중 사용자가 채택한 비율을 기록한다. 배치마다 낮아지면 프롬프트를 고친다.
- 반영 후 사용자가 다시 고친 비율을 기록한다. 이 값이 높으면 기준이 AI 취향에 기운 것이다.
- 기록 위치: `study-audits/`와 배치별 검수 로그(`drafts/ai-review/`, 제안).

## 7. 위험과 대응

| 위험 | 대응 |
|---|---|
| 자연스러움을 이유로 사실·수치가 바뀜 | `meaning_change` 표시, 사실 대조 단계, 자동 채택 금지 |
| 번역투 과교정 | "자연스러운 쪽 고르기" 판정, 피동·‘-되다’ 일괄 금지 안 함 |
| 두 AI가 같은 편향을 공유함 | 서로 다른 제공자 사용, blind 검수, Claude가 판정 |
| 편향·자기 선호 | 순서 교차, 자기 결과 자기 판정 금지 |
| 기준 문서 간 충돌 | 0단계에서 체크리스트 하나로 합치고, 충돌 항목은 사용자에게 묻는다 |
| 비용과 호출 한도 | 기계 점검 먼저, 배치 단위 호출, 파일럿 후 확대 |
| 외부 서비스에 원고 전송 | 공개된 사이트 원고만 보낸다. 개인 정보는 넣지 않는다 |
| 도구 미연결(Gemini 키, Codex 로그인) | 실행 전에 연결을 확인한다. 안 되면 해당 단계를 멈추고 사유를 보고한다 |

## 8. 확인하지 않은 것

- Gemini API 키와 Codex(ChatGPT) 로그인이 지금 동작하는지 확인하지 않았다. `ai-orchestrator/.env`와 `codex login`은 실행 전에 확인해야 한다.
- 웹 조사 결과는 검색 요약과 초록 기준이다. 원문은 읽지 않았다.
- 2026년 국립국어원 공식 교정 지침은 찾지 못했다.
- 강의 원고의 현재 상태(필드별 글자 수, 위반 수)는 아직 측정하지 않았다. 0단계에서 측정한다.

## 9. 결정이 필요한 항목(사용자 확인)

1. 배치 크기: 3편 × 7배치로 충분한가요?
2. 파일럿 3편(김주환 강의) 후보를 그대로 쓸까요?
3. 검수 로그를 저장소 `drafts/ai-review/`에 둘지, 외부(노션 등)에 둘지 정해 주세요. 현재 제안은 저장소 안입니다.
4. 기계 점검에 쓸 체크리스트는 기준 문서 중 어느 쪽을 우선할지 정해 주세요. 두 문서의 세부 기준이 실제로 같은지는 아직 대조하지 않았습니다(0단계에서 확인).
