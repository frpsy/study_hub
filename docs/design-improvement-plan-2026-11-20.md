# 디자인 개선 계획 (2026-11-20)

> 계획 문서다. 이 문서만으로는 화면이 바뀌지 않는다. 각 단계는 별도 PR로 구현하며, 구현할 때 `docs/design-system.md`·토큰·검사를 같은 PR에서 갱신한다.

## 1. 목적과 범위
- **목적:** v15 「조용한 서재」 방향을 유지한 채 "첫 화면에서 한 문장이 바로 보이게" 하고 머리 영역의 군더더기를 줄인다.
- **근거:** 2026-11-20 홈·강의 페이지를 390px·1280px에서 캡처해 확인했다.
  - 모바일 강의 첫 화면에서 한 문장은 약 470px(844px 화면 기준)에 놓여 제목·메타·목차·"핵심 요약" 제목 아래로 밀려 있다. (처음 계획에는 '스크롤해야 보인다'고 적었으나 실측 결과 보이기는 한다. 위치를 올리는 것으로 목표를 바꾼다.)
  - 머리 영역(제목 → 메타 → 목차 → "핵심 요약" → "한 문장" 라벨) 사이 여백이 크고, "핵심 요약"과 "한 문장"이 이중 제목처럼 읽힌다.
  - 홈은 검색 → 칩 → 정렬 → 목록 단계가 많아 목록에 닿기까지 길다.
- **사용자 불편 사항:** 아직 듣지 못했다. 불편 사항을 들으면 아래 우선순위를 조정한다.

## 2. 유지할 것 (비목표)
- 색 토큰, 라이트·다크, 강조 색 선택, 760px 읽기 폭, 상단 메뉴 없음, 웹폰트 없음.
- 학습 기록·이어 읽기·로그인 화면은 되살리지 않는다.
- 강의 본문, 타임스탬프 원문과 복사 결과, 기존 URL 앵커는 바꾸지 않는다.
- 새 색상·반경·간격 값은 만들지 않고 기존 토큰을 쓴다.

## 3. 접근 방식
| 안 | 내용 | 평가 |
|---|---|---|
| A. 첫 화면 정돈 (추천) | 강의 머리 간격·구조만 조정, 홈은 검색 영역 압축 | 위험 작음, 효과 큼. v15 방향과 일치 |
| B. 전면 재디자인 | 새 레이아웃·타이포 | 기존 결정과 검사 전부 흔들림. 제외 |
| C. 현 상태 유지 | 문서만 정리 | 첫 화면 문제가 남음. 제외 |

추천: **A**. 사용자가 "추천안대로 진행"으로 선택했다.

## 4. 단계별 계획
1. **강의 머리 압축 (최우선)**
   - 브레드크럼·제목·메타 사이 세로 간격을 한 단계씩 줄여, 모바일(390×844) 첫 화면에서 한 문장의 위치를 위로 올린다.
   - "핵심 요약" 제목과 "한 문장" 라벨의 중복을 줄인다(라벨 제거 또는 제목과 통합). `.eyebrow` 한 문장 라벨이 접근성 이름에 필요한지 확인한 뒤 결정한다.
   - 목차(`reading-nav`) 높이와 `--anchor-offset` 계산이 바뀌면 앵커 위치 검사를 함께 갱신한다.
2. **홈 첫 화면 정리**
   - 모바일에서 검색 → 칩 → 정렬 사이 간격을 줄이고, 첫 강의 제목이 첫 화면 위쪽에 오게 한다.
   - `오늘의 한 문장`의 출처 줄과 부제목 중복 여부를 검토한다.
3. **읽기 흐름 점검**
   - 상세 요약·실천 포인트의 섹션 간 간격을 같은 기준으로 맞춘다. 소제목 선·문단 굵기(v14)는 유지한다.
4. **마무리**
   - `build-info.json` 버전을 올리고 재생성한다. `design-system.md`에 "v2026.11.xx 첫 화면 정돈" 항목을 추가한다.

## 5. 검증
- 기준 화면: 360·390·1280px, 라이트·다크, 글자 크기 작게·보통·크게.
- 변경 전후 캡처를 비교하고, 한 문장이 첫 화면(844px 높이)에 들어오는지 측정한다.
- AGENTS.md의 전체 검증 명령(디자인·사이트 검사, `--check` 빌드, unittest, node test, playwright)을 모두 통과시킨다.
- 실기기 Safari는 검증하지 못하므로 PR의 남은 위험에 적는다.

## 6. 위험과 확인 필요
- 간격 변경이 기존 계산 스타일 테스트나 앵커 오프셋 검사를 깰 수 있다.
- 한 문장 라벨 제거가 스크린리더 구조에 영향을 주는지 구현 때 확인한다.
- 사용자 불편 사항에 따라 우선순위가 바뀔 수 있다.
