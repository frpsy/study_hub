# 강의 상세 요약의 무손실 윤문

새 YouTube 요약을 작성하거나 기존 강의의 상세 본문을 손볼 때 항상 적용한다. `AGENTS.md`, `편집규칙.md`, `lecture-study`와 함께 읽는다. 사용자의 더 구체적인 지시가 우선한다.

1. HTML 생성 경로부터 확인한다. study_hub에서는 `data/lecture_compact.json`의 `detail[].h`와 `detail[].p`를 먼저 수정하고 공통 생성기로 HTML을 만든다. 생성 HTML을 직접 고치지 않는다.
2. 한 번에 강의 세 개씩 순서대로 읽고 교정한다. 마지막 잔여 배치는 세 개 미만이어도 된다. 전체 문맥을 읽은 뒤 문장을 고친다. 단순 정규식 일괄 치환으로 윤문을 대신하지 않는다.
3. 강연자·강의를 주어로 삼는 중계형 표현을 없애고 논지 자체를 `~다/~이다`의 비경어체로 서술한다. 연구자·실험 행위자의 이름과 역할은 사실 정보이므로 보존한다. 가능성·가설·조건·연구 한계의 강도를 바꾸지 않는다.
4. 불필요한 지시대명사, 피동, 명사화 연쇄, 자막의 어색한 조사·띄어쓰기를 문맥에 맞게 다듬는다. 짧고 긴 문장을 섞어 인과·대조·전환을 자연스럽게 잇는다. 뜻이 명확한 기존 문장은 억지로 바꾸지 않는다.
5. 소제목은 핵심이 선명한 질문형(`~인가/~는가`)으로 쓴다. 소제목을 바꾼 뒤 홈의 ‘해당 부분 읽기’ 링크와 상세 목차가 같은 문자열로 생성되는지 검증한다.
   상세 요약의 서로 다른 소제목에서 핵심 문장 3~5곳을 고른다. 강조할 문장을 해당 소제목의 `highlight`에 본문과 동일하게 기록하고, 문장을 윤문할 때 강조 원문도 함께 맞춘다.
6. 실험·학자·수치·비유·실천 방법·조건·논리 전개를 삭제하거나 요약하지 않는다. 외부 지식을 끼워 넣지 않는다. 전문 용어의 표기를 임의로 바꾸지 않는다. 오인식이 의심되면 보관 자막과 앞뒤 문맥을 확인하고 근거를 남긴다.
7. 문단·목록·이미지·인용의 구조와 순서, 직접 인용, `detail-*` id, CSS 클래스, 타임스탬프와 출처를 보존한다. 문단을 통째로 없애거나 목록을 문단으로 바꾸지 않는다.
8. 배치마다 생성·무결성 검사를 한 뒤 수정 파일과 대표 Before/After 3~5건을 짧게 보고한다. 자료를 줄인 요약을 윤문 완료로 보고하지 않는다.
9. 전체가 끝나면 모든 홈 `#detail-*` 링크와 실제 소제목의 100% 일치, 앵커·태그 구조·수치·용어·인용·타임스탬프 보존을 전수 확인한다. 정적·브라우저·CI 검사 → PR 머지 → 공개 배포 확인까지 완료한다.
10. 검토 범위와 한계는 감사 기록에 남긴다. 독립 AI 검수나 원문 전체 대조를 하지 않았다면 수행했다고 쓰지 않는다.

## 다음 요약에 교정을 반영하는 방법

1. 초안 전에 [교정 기록](../../../docs/lecture-polish-audit-2026-11-25.md)에서 같은 형식이나 주제의 사례를 읽는다. 강의별 `study-audits/<영상ID>.json`과 원본 자막을 찾아 주장, 연구 결과, 개인 경험, 실천 권유를 구분한다.
2. 초안에서는 누가 무엇을 했는지, 어떤 조건에서 결과가 나타났는지 먼저 쓴다. 첫 문장을 소리 내어 읽고 주어와 서술어의 호응을 확인한다. 핵심 문장과 상세 목차를 각각 따로 읽어, 앞뒤를 보지 않아도 무엇을 가리키는지 확인한다. ‘이야기가 멈춘다’ 같은 비유는 ‘일이 왜 일어났는지 모를 때 억지로 이유나 의미를 붙이지 않는다’처럼 실제 뜻을 쓴다. ‘이를’, ‘이 관점’, ‘같은 일’의 대상을 바로 짚기 어렵거나 ‘고른 선택’처럼 말이 겹치면 고친다.
3. 근거와 표현을 따로 검토한다. 댓글의 언급 빈도는 효과의 크기로, 강의의 설명 모형은 검증된 인과관계로 바뀌지 않았는지 확인한다. 수치와 예외를 한 문단에서 살리고, 관점이나 제안의 출처가 의미를 제한하면 밝혀 둔다. 의심스러운 문장은 자막의 앞뒤 발화까지 확인한다.
4. 화면에서 홈 대표 한 문장, 핵심 요약, 상세 목차를 읽는다. 독자가 읽기 시간과 영상 길이처럼 서로 다른 정보를 구분할 수 있는지도 확인한다. 대표 문장의 길이와 동기화는 `tests/test_korean_leads.py`가 검사한다.
5. 새로운 오류나 사용자 교정을 발견하면 강의 ID와 위치, 원문 근거 또는 사용자 지적, 전후 문장, 다음에 적용할 질문을 교정 기록에 덧붙인다. 같은 문제가 되풀이되면 이 절의 질문을 고친다. 뜻에 관계없이 찾아낼 수 있는 오류라면 기존 검증에 사례를 추가하고, 문맥이 필요한 표현은 사람이 검토한다.
