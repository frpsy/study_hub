# 강의 윤문: 내용을 보존하며 한국어를 다듬는다

**적용 범위.** 이 저장소(frpsy/study_hub)의 강의 요약 작성·수정과 상세 본문 윤문에 자동 적용한다. 다른 저장소나 일반 문서에는 적용하지 않는다. `AGENTS.md`, `편집규칙.md`, `docs/kimjuhwan-style.md`, `lecture-study`와 함께 읽는다. 사용자의 더 구체적인 지시가 우선한다.

## 1. 원칙: 윤문은 요약이 아니다
- 윤문은 기존 문장의 정보·의미·조건·논리 전개를 보존하면서 한국어 표현을 개선한다. 분량을 줄이려고 재요약하지 않는다.
- 정보 보존이 길이 제한과 문체 통일보다 우선한다. 보존 대상은 실험 사례, 학자 이름과 역할, 수치, 비유, 실천 방법, 전문 용어, 조건, 직접 인용이다.
- 가능성·가설·상관관계·조건부 결과를 확정 사실이나 인과관계로 강화하지 않는다.
- 원문에 없는 설명·처방·기간·효과를 추가하지 않는다. 웹에서 찾은 내용도 본문에 섞지 않는다(편집자 주에만 쓴다, `편집규칙.md` 17절).
- 강연자의 개인 경험과 연구자의 역할은 사실 정보이므로 보존한다.
- 이미 자연스럽고 정확한 문장은 억지로 바꾸지 않는다.

## 2. 자연스러운 한국어
- 중계형 서술(“강연자는 ~라고 말한다”, “강의는 ~를 살펴본다”)을 없애고 핵심 논지를 직접 서술한다.
- 주장 주체나 출처를 지우면 의미가 달라지는 곳에는 필요한 귀속과 한정을 남긴다.
- 불필요한 지시대명사, 번역투, 피동, 명사화 연쇄, 어색한 조사와 연결을 다듬는다.
- 차분한 평서형(~다, ~이다)을 쓴다. 기계적 어미 치환이나 정규식 일괄 치환으로 윤문하지 않는다.
- 광고성 과장, 불필요한 감탄, 수사적 질문을 피한다.

## 3. 편집 대상별 기준
- 시작 전에 범위를 정한다: 한 줄 요약(`lead`), 핵심 항목(`points`), 상세 본문(`detail`) 가운데 무엇을 고치는지 확인한다. 범위가 분명하면 재확인 없이 진행한다.
- **한 줄 요약**은 공백 포함 35~65자의 한 문장이며 메타 주어를 쓰지 않는다. 카드와 ‘오늘의 한 문장’에서 390px 폭에 두 줄 안에 읽혀야 한다(`tests/home-discovery.spec.cjs`가 전 강의를 검사한다). 글자 수는 목표이고, 판정은 이 두 줄 표시 검사다. 도입 문장의 90자·쉼표 규칙도 목표이며 어색하게 줄이지 않는다(편집규칙 19절). 길이를 맞추려고 핵심 정보나 조건을 지우거나 CSS로 잘라 숨기지 않는다.
- 상세 소제목은 질문형(~인가, ~는가)을 유지한다.
- 상세 본문은 분량을 줄이는 방향으로 재요약하지 않는다.
- **핵심 문장 강조(`highlight`).** 상세 요약의 서로 다른 소제목에서 핵심 문장 3~5곳을 고른다. 강조할 문장을 해당 소제목의 `highlight`에 본문과 동일하게 기록하고, 문장을 윤문할 때 강조 원문도 함께 맞춘다.

## 4. 원본과 화면 동기화
- 먼저 HTML이 정적인지 생성 구조인지 확인한다. study_hub는 생성 구조다.
- 원본을 고친다: `data/lecture_compact.json`의 `detail`·`intro`, `data/mini_courses.json`의 `lead`. 그다음 `python3 scripts/build_all.py --check --tests`로 재생성·검사한다. 생성 HTML은 손으로 고치지 않는다.
- 한 줄 요약은 `mini_courses.json`의 `lead`와 `intro` 첫 `points` 항목을 같은 문장으로 맞춘다. 카드, ‘오늘의 한 문장’, 상세 상단, 공유 설명이 같은 문장을 쓰는지 확인한다.
- 소제목을 바꾸면 홈의 ‘해당 부분 읽기’ 링크와 상세 목차가 같은 문자열과 앵커를 쓰는지 `scripts/validate_detail_sync.py`로 확인한다.
- DOM 구조, `detail-*` 앵커, CSS 클래스, 타임스탬프, 직접 인용, 출처, 이미지는 보존한다.

## 5. 작업 순서와 검증
1. 강의를 세 편씩 순서대로 읽고 고친다. 마지막 잔여 배치는 세 편 미만이어도 된다. 전체 문맥을 읽은 뒤 문장을 고친다.
2. 수정 전 문장을 보관하고, 강의별 Before/After를 `docs/` 아래 감사 기록(예: `docs/lecture-polish-audit-2026-11-24.md`)에 남긴다.
3. 배치마다 생성과 무결성 검사를 마친 뒤 수정 파일과 대표 Before/After 3~5건을 짧게 보고한다.
4. 정보 보존(수치, 인용, 전문 용어, 구조)과 표현의 자연스러움을 따로 검토한다.
5. `scripts/audit_lecture_polish.py --baseline-ref <커밋>`은 수치·인용·용어·구조 보존을 대조하는 보조 도구다. 의미가 보존되었다고 증명하지 않으므로 문맥 검토를 함께 한다.
6. 정적·생성·단위·브라우저 검사와 PR, CI, 병합, 공개 페이지 확인은 `AGENTS.md`의 절차를 따른다.

## 6. 보고 기준
- 수행하지 않은 영상·자막 대조, 독립 AI 검수, 원문 전체 대조를 수행했다고 쓰지 않는다.
- 자료를 줄인 요약을 윤문 완료로 보고하지 않는다.
- 검토 범위와 한계는 감사 기록과 PR의 ‘남은 위험’에 적는다.

## 7. 다음 요약에 교정을 반영하는 방법

1. 초안 전에 [교정 기록](../../../docs/lecture-polish-audit-2026-11-25.md)에서 같은 형식이나 주제의 사례를 읽는다. 강의별 `study-audits/<영상ID>.json`과 원본 자막을 찾아 주장, 연구 결과, 개인 경험, 실천 권유를 구분한다.
2. 초안에서는 누가 무엇을 했는지, 어떤 조건에서 결과가 나타났는지 먼저 쓴다. 첫 문장을 소리 내어 읽고 주어와 서술어의 호응을 확인한다. 핵심 문장과 상세 목차를 각각 따로 읽어, 앞뒤를 보지 않아도 무엇을 가리키는지 확인한다. ‘이야기가 멈춘다’ 같은 비유는 ‘일이 왜 일어났는지 모를 때 억지로 이유나 의미를 붙이지 않는다’처럼 실제 뜻을 쓴다. ‘이를’, ‘이 관점’, ‘같은 일’의 대상을 바로 짚기 어렵거나 ‘고른 선택’처럼 말이 겹치면 고친다.
3. 근거와 표현을 따로 검토한다. 댓글의 언급 빈도는 효과의 크기로, 강의의 설명 모형은 검증된 인과관계로 바뀌지 않았는지 확인한다. 수치와 예외를 한 문단에서 살리고, 관점이나 제안의 출처가 의미를 제한하면 밝혀 둔다. 의심스러운 문장은 자막의 앞뒤 발화까지 확인한다.
4. 화면에서 홈 대표 한 문장, 핵심 요약, 상세 목차를 읽는다. 독자가 읽기 시간과 영상 길이처럼 서로 다른 정보를 구분할 수 있는지도 확인한다. 대표 문장의 길이와 동기화는 `tests/test_korean_leads.py`가 검사한다.
5. 새로운 오류나 사용자 교정을 발견하면 강의 ID와 위치, 원문 근거 또는 사용자 지적, 전후 문장, 다음에 적용할 질문을 교정 기록에 덧붙인다. 같은 문제가 되풀이되면 이 절의 질문을 고친다. 뜻에 관계없이 찾아낼 수 있는 오류라면 기존 검증에 사례를 추가하고, 문맥이 필요한 표현은 사람이 검토한다.
